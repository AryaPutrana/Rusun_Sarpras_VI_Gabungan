🔴 BUG #1: AUTHENTICATION SECURITY VULNERABILITY (CRITICAL)
═══════════════════════════════════════════════════════════════════════════════

╔═══════════════════════════════════════════════════════════════════════════╗
║ BUG DETAILS                                                               ║
╚═══════════════════════════════════════════════════════════════════════════╝

Severity:           🔴 CRITICAL - Security Vulnerability
Module:             Authentication System
File:               app/Http/Controllers/AuthController.php
Lines:              53-65 (BEFORE fix)
Discovery Method:   Automated security testing (Subagent #1)
Impact:             High - Security window allows invalid role users to 
                    receive authenticated session momentarily

╔═══════════════════════════════════════════════════════════════════════════╗
║ ROOT CAUSE                                                                ║
╚═══════════════════════════════════════════════════════════════════════════╝

BEFORE (VULNERABLE):
┌───────────────────────────────────────────────────────────────────────────┐
│ 1. Auth::attempt() executes FIRST                                        │
│    → User authenticated                                                   │
│    → Session created                                                      │
│    → Auth events fire                                                     │
│                                                                           │
│ 2. Role check happens AFTER authentication                                │
│    → if role not in ['admin', 'petugas']                                 │
│    → Auth::logout() called                                                │
│    → Session invalidated                                                  │
│    → Token regenerated                                                    │
│                                                                           │
│ SECURITY WINDOW: Between step 1 and 2, invalid user is authenticated!   │
└───────────────────────────────────────────────────────────────────────────┘

Security Risks:
• Session fixation attacks possible
• Audit logs show invalid users as "authenticated"
• Event listeners receive authenticated invalid users
• Race conditions in concurrent requests
• Potential privilege escalation window

╔═══════════════════════════════════════════════════════════════════════════╗
║ FIX APPLIED                                                               ║
╚═══════════════════════════════════════════════════════════════════════════╝

Strategy: PRE-VALIDATE role BEFORE calling Auth::attempt()

AFTER (SECURE):
┌───────────────────────────────────────────────────────────────────────────┐
│ 1. Query user by email (without authentication)                           │
│    → $user = User::where('email', $credentials['email'])->first();       │
│                                                                           │
│ 2. Validate role BEFORE authentication                                    │
│    → if ($user && !in_array($user->role, ['admin', 'petugas']))         │
│    → Increment login attempts                                             │
│    → Return error: "Akun Anda tidak memiliki akses ke sistem"           │
│    → NO session created                                                   │
│                                                                           │
│ 3. Only authenticate if role is valid                                     │
│    → Auth::attempt() called only for valid roles                          │
│    → Session created only for authorized users                            │
│                                                                           │
│ SECURITY WINDOW CLOSED: Invalid users never get authenticated!           │
└───────────────────────────────────────────────────────────────────────────┘

╔═══════════════════════════════════════════════════════════════════════════╗
║ CODE CHANGES                                                              ║
╚═══════════════════════════════════════════════════════════════════════════╝
